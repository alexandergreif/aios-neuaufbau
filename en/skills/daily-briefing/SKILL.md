# Daily Briefing

Follow the [core rules](../../rules/core.md) and for the output file the [storage reference](../../references/storage.md). Use the approved sources needed for the specific day. If a needed source or access is missing, name the gap and ask first about how to proceed. Wait for this decision before you output or save a briefing on a limited basis.

On invocation, create a short briefing with the most important next step, today's appointments, your own open and due to-dos, relevant Jira items and important messages that need a decision or reply. Search specifically by time range and topic. Separate appointments with other people from work you blocked for yourself. If the appointment type is unclear, name the uncertainty. Only calculate free time if calendar coverage and the data needed for it are complete enough. Do not assume fixed working hours or warning thresholds.

Combine the same matter from several sources into one point and name the evidence. Compare with the last short daily briefing result, if one exists in the personal output folder. Check earlier open or unclear points against current sources. Missing hits, past appointments or shifted work blocks do not prove completion. Carry over only brief identifiers and statuses, not full emails or chats. Do not read old briefings from a previous installation.

Show source coverage and gaps. Save the new short briefing as an output file in the personal output folder per the storage reference, so the next daily briefing has a limited comparison. The history is not a second task list or knowledge store. A briefing task does not allow external write actions: send nothing and do not change tasks, tickets or appointments.
