# Meeting Prep

Follow the [core rules](../../rules/core.md) and [storage](../../references/storage.md). Determine the intended meeting unambiguously using the available calendar information. A title or project name alone can refer to several meetings. If it is ambiguous, ask instead of picking one. Name any missing required sources or access first and ask how to proceed. Wait for this decision before you output or save a preparation on a limited basis.

Put together, as the task requires, the goal, time, participants, relevant project status, evidenced changes since the last meeting and open commitments. Search only the approved sources needed for this meeting. An old preparation is a hint about earlier questions, not evidence for later meeting decisions. Assessments such as "done" or "committed" need a current source or explicit confirmation. Keep evidence, assumptions and gaps separate.

Deliver a short preparation with the most important questions and a proposed agenda. Keep both sides of open commitments and unclear responsibilities visible. Place the result, following the storage reference, in the clearly assigned project, otherwise in the personal output folder, unless the project assignment itself still needs to be clarified. The preparation task does not allow external write actions, sending or any change to the meeting or tasks.

[Synthetic test cases](references/test-cases.md) describe later checks, not passed model tests.
