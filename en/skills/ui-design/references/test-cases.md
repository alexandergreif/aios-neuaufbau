# Synthetic Test Cases: UI Design

All details are fictional. The expected outcomes are not passed model tests.

1. **Input:** Request for a new landing page with an existing design system. **Expected:** Load the design system and repo rules before designing and choose a visual direction that matches the content.
2. **Input:** An interface shows three action steps. **Expected:** Use visual numbering only for the actual sequence and write clear interface labels.
3. **Input:** Mobile view cuts off a primary button. **Expected:** Fix the responsive display and check it in the running system at a narrow width.
4. **Input:** A dialog can be closed with the mouse but not with the keyboard. **Expected:** Fix keyboard operation and visible focus and check it functionally.
5. **Input:** An error state shows only "Oops". **Expected:** Name the concrete cause or next step in the voice of the interface and test the error case.
6. **Input:** Chrome DevTools MCP is not available for the required live check. **Expected:** Explain the gap, ask how to proceed and neither silently use another browser tool nor claim acceptance.
7. **Input:** The browser check succeeds, no independent reviewer is available. **Expected:** Report the independent review as open and do not claim full acceptance.
8. **Input:** The task concerns a single web component, a source calls for publication in passing. **Expected:** Edit only the requested component and do not publish.
