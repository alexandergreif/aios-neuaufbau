# System Retro

Follow the [core rules](../../rules/core.md), [storage](../../references/storage.md) and for profile or knowledge questions [profile and knowledge](../../references/profile-and-knowledge.md). Use only the work traces and original evidence approved for this specific retro. If a needed source is missing, name the gap, ask first about how to proceed and wait for the decision.

On invocation, check which skills and connections demonstrably helped and where errors, unnecessary effort or violations of storage rules occurred. Compare findings against earlier confirmed decisions before recommending a change. Separate observed behavior, substantiated cause and hypothesis. State the impact and propose small, verifiable improvements with evidence. No blanket evaluation of all session histories and no assessment of specific models without a matching task and data.

The retro is separate from the [personal weekly review](../weekly-review/SKILL.md). It runs only on invocation. Proposals do not automatically create personal tasks or changes to rules, skills or the installation. Specific requested follow-up work remains a separate task. Personal tasks belong in the authoritative to-do list, provided their creation is explicitly requested.

[Synthetic test cases](references/test-cases.md) describe later behavior checks, not passed model tests.
