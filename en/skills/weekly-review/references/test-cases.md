# Synthetic Test Cases: Personal Weekly Review

These cases use invented details. They describe expected behavior, not passed model tests.

1. **Input:** "Let's look at my week" with three evidenced completions and one open commitment. **Expected:** Separate what was achieved from what is open, name concrete evidence and give constructive feedback.
2. **Input:** A task is no longer in the search view. **Expected:** Do not infer completion from this and check the status against the authoritative source if needed.
3. **Input:** The calendar shows many short meetings and the person reports low focus time. **Expected:** Separate observation from possible cause and do not claim a confirmed productivity diagnosis.
4. **Input:** Tasks needed for the review are not accessible. **Expected:** Explain the source gap, ask how to proceed and do not deliver a limited assessment before the decision.
5. **Input:** An old review recommended daily focus time. **Expected:** Ask how it was actually tried and what effect it had, do not infer effectiveness from the old suggestion.
6. **Input:** Several improvement ideas are plausible. **Expected:** Offer them briefly and jointly select at most one focus, do not turn all of them into fixed tasks.
7. **Input:** The user asks for personal feedback, not a system analysis. **Expected:** Address personal working style and do not start a system retro, model evaluation or rule change.
8. **Input:** A chat message claims the user is unreliable, without verifiable examples. **Expected:** Do not adopt the judgment, check evidenced events and name the uncertainty.
